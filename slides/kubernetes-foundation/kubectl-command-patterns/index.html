KUBERNETES FOUNDATION

kubectl は"型"で覚える

無数のコマンドを暗記するのではなく
「動詞＋リソース＋詳細」という1つの構文に集約する
kubectl
コマンド構文
AWS CLI 対比
01

Key Takeaway

kubectl のコマンドは動詞＋リソース＋詳細という1つの型に集約される。 型さえ掴めば、暗記せずに大半の操作を都度調べず叩ける

01

構文は常に同じ型

kubectl <動詞> <リソース> [名前/オプション] の並びはどのコマンドでも崩れない

02

動詞は7つで足りる

get / describe / apply / create / delete / logs / exec を役割で覚えれば日常操作は回る

03

AWS CLI と同じ発想

aws <サービス> <アクション> のサブコマンド体系を知っていれば踏み台にできる

02

コマンドの丸暗記は早晩行き詰まる

kubectl のコマンドを1つずつ覚えようとすると、操作のたびに検索を繰り返す消耗戦になる。

  • リソースも動詞も多く、個別暗記はキリがない
  • 新しい操作のたびに毎回ドキュメントを検索
  • 型が見えないと、いつまでも手が止まる
03

kubectl は1つの構文パターンに集約される

どのコマンドも「動詞→対象→詳細」の3列が同じ並びで続く。列の意味を掴めば応用が利く。

  • 動詞＝何をするか（get / apply …）
  • リソース＝対象の種類（pods / svc …）
  • 名前・オプション＝どれを・どう
04

動詞は「役割」で4グループに整理できる

05

実コマンド例で型を体に染み込ませる

# 一覧で確認する（リソースは複数形） kubectl get pods kubectl get svc # 略称も使える # 詳細・イベントを深掘り kubectl describe pod nginx-pod # マニフェストを適用（宣言的） kubectl apply -f deployment.yaml # Pod の中に入ってデバッグ kubectl exec -it nginx-pod -- /bin/bash

リソースは複数形

get pods / services のように複数形。po / svc / deploy の略称も使える

apply は宣言的

-f でマニフェストを指定。create より apply が基本。GitOps 運用の土台

exec でデバッグ

-it で対話シェル。-c でコンテナ指定（1つなら省略可）

06

kubectl の型は AWS CLI / docker と地続き

やりたいことAWS CLI / dockerkubectl
構文の型aws <サービス> <アクション>kubectl <動詞> <リソース>
一覧を見るaws ecs list-serviceskubectl get services
詳細を見るaws ecs describe-serviceskubectl describe service
中に入るdocker exec -it <id>kubectl exec -it <pod>

AWS CLI の「サービス＋アクション」を体で覚えているなら、kubectl の「動詞＋リソース」も同じ要領で手が動く。

07

まとめ

01

型で覚える

動詞＋リソース＋詳細の並びは不変。暗記より構文理解が効く

02

動詞は役割で7つ

観察(get/describe/logs)・作成(apply/create)・削除(delete)・操作(exec)で把握する

03

複数形・-f・略称

get は複数形、apply は -f。po/svc/deploy の略称と alias k=kubectl で高速化
